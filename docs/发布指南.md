# Galaxy View 发布指南

> 给「三个月后没有上下文的我」：怎么把这个本地插件发到 GitHub、给 BRAT 用、最终上架 Obsidian 社区商店。
> 当前状态：`0.6.1` 已于 2026-07-29 发布为 Latest；仓库为 `Longwind1984/galaxy-view`。

## 0. 发布前置

先确认 GitHub CLI 的登录与 Git 传输都正常：

```bash
gh auth status
git ls-remote origin HEAD
```

若凭据失效，用 `gh auth login` 重新登录。`0.6.1` 发布时，本机 HTTPS／SSH 传输均被网络层阻断，因此改用 GitHub App 合并 PR、网页上传资产；Release 有公开 SHA-256 核验，但没有 tag-push 工作流提供的 Actions provenance。后续版本应优先恢复下面的自动发布链路。

## 1. 合并发布分支

仓库根目录是 `/Users/rick/Claude_Code/Galaxy_View`，远端为 `https://github.com/Longwind1984/galaxy-view.git`。发布分支先通过 PR 合入 `main`，不要直接在脏工作区打 tag。

```bash
cd /Users/rick/Claude_Code/Galaxy_View
git switch main
git pull --ff-only
```

> 注意 `.gitignore` 已排除 `dev-vault/`（你笔记的本地克隆）、`node_modules/`、`main.js`、`dist/`——不会把你的笔记或构建产物推上去。

## 2. 打 tag 触发自动发布

CI（`.github/workflows/release.yml`）监听 tag push：自动跑 lint + test + build，然后把 `main.js`/`manifest.json`/`styles.css` 作为 release 资产发布。

```bash
node -p "require('./manifest.json').version"
git tag -a 0.6.2 -m "Release 0.6.2"
git push origin 0.6.2
```

tag 必须与 `manifest.json` 的 `version` 完全一致，且不带 `v` 前缀。去仓库 Actions 页确认 Release 工作流成功；Releases 页应出现同版本的正式 Release、三个插件附件与 provenance attestation。

若自动链路不可用但必须发布，可在 GitHub Release 页面从 `main` 创建同版本 tag，再上传本地 `npm run build` 生成的 `dist/main.js`、`dist/manifest.json`、`dist/styles.css`。发布后必须逐一核对远端资产 SHA-256；不得把这种手动路径描述成 Actions 构建。

## 3. 用 BRAT 安装（beta 分发 / 浸泡测试）

1. 在任意 vault 装 BRAT 插件（社区商店搜 "BRAT"）
2. BRAT → Add beta plugin → 填 `Longwind1984/galaxy-view`
3. 自动拉取最新 release 并安装

BRAT 会跟随 Latest Release，适合发布前持续浸泡和验证升级路径。

## 4. 上架社区商店（可选，浸泡满意后）

官方流程（2026 年起走 portal，非旧的 PR-to-obsidian-releases）：

1. 浏览器开 `community.obsidian.md`，用 Obsidian 账号登录，关联 GitHub 证明仓库归属
2. Plugins → New plugin → 同意开发者政策
3. 自动审核给反馈；要改就发新 release（version 必须 bump，`npm version patch` 会自动改 manifest+versions 并打 tag）
4. **提交时先查重**：商店里搜 `galaxy-view` / `Galaxy View` 确认 id 与名称未被占用（id 规则：不得含 "obsidian"，已满足）

商店素材还需要：截图 / GIF（README 里目前没有；找几张深空 + 银河预设 + 聚焦卡片的效果图）。

## 版本号怎么涨

```bash
npm version patch    # 0.6.1 → 0.6.2：同步 package / manifest / versions 并创建 git tag
git push origin main
git push origin 0.6.2
```
`versions.json` 记录每个插件版本要求的最低 Obsidian 版本（当前 `0.6.1: 1.8.7`）。
